# Dataset documentation (synthetic movie platform)

The dataset is generated by `src/ingestion/generate_synthetic.py` with `seed: 42`
(`configs/config.yaml`). The same seed always produces byte-identical files; the MD5
checksums are recorded in `reports/ingestion_manifest.json`. A copy of the generated
raw data is committed in `data/raw/source/`.

To use real data instead, download MovieLens `ml-latest-small` into
`data/external/ml-latest-small/` and set `ingestion.source: movielens`.

## Tables (raw, as delivered to the pipeline)

| Table | File | Rows* | Columns |
|---|---|---:|---|
| users | `data/raw/source/users.csv` | 1,010 | user_id, age, gender, country, signup_date |
| items | `data/raw/source/items.csv` | 606 | item_id, title, genres (pipe-separated), release_year, duration_min |
| interactions | `data/raw/source/interactions.csv` | 59,891 | user_id, item_id, rating (1–5), timestamp |

\* including injected duplicates and corrupt rows. The clean core has 1,000 users, 600 movies, 12 genres
and about 58.7k ratings between 2023-01 and 2026-10.

## How the data are generated

* **Items:** each movie gets 1–3 genres, a hidden "quality" ~ N(0, 0.45) and a Zipf-like
  popularity (exponent 0.7), giving a realistic long tail.
* **Users:** each user has a sparse genre-taste vector ~ Dirichlet(0.35), a rating bias ~ N(0, 0.35)
  and a log-normal activity level (a few heavy users, many light users; min 5 ratings).
* **Choice:** P(user picks movie) ∝ popularity × exp(6 × taste match). Popularity and personal
  taste both matter, so a personalised model has real signal to learn and a popularity model is a
  strong but beatable baseline.
* **Rating:** 3 + quality + user bias + 2.2 × (taste match − mean match) + N(0, 0.55),
  rounded and clipped to 1–5.
* **Time:** each rating happens after the user's sign-up date and before 2026-10-31.

## Data-quality problems injected on purpose (about 2% per table)

| Table | Problem | How the pipeline handles it |
|---|---|---|
| users | missing age, country | warning → imputed (median age, "Unknown") |
| users | impossible age (-3, 0, 142, 230, "unknown") | warning → set to null → imputed, flagged in `age_imputed` |
| users | inconsistent gender labels (" male", "female ") | warning → standardised to M / F / Other |
| users | bad date "31/02/2024" | warning → signup_date set to null |
| users | duplicate records | error → quarantined |
| items | missing genres, lower-case genres | warning → "Unknown" / Title-Case |
| items | release year 1066 / 3021 | warning → median imputation |
| items | duplicate records | error → quarantined |
| interactions | rating 0, 6, 7, -1, 10 | error (`rating_out_of_range`) |
| interactions | rating "five", "N/A", "4 stars" | error (`rating_wrong_type`) |
| interactions | missing rating / user_id / timestamp | error (`missing_*`) |
| interactions | timestamp "not_a_date", "2024-13-45…", "12/05/2024" | error (`timestamp_unparseable`) |
| interactions | timestamp in 2031 / in 1999 | error (`timestamp_in_future` / `timestamp_too_old`) |
| interactions | unknown user / item IDs | error (`orphan_user_id` / `orphan_item_id`) |
| interactions | exact duplicate rows | error (`exact_duplicate`) |
| interactions | same user re-rates a movie 3 days later | not an error → preparation keeps the latest rating |

The exact counts per rule are in `reports/validation_report.md`.
